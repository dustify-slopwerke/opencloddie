# Deploying opencloddie

> This reference deployment targets an edge nginx + Authelia stack.  Paths such
> as `~/compose/edge` are examples; adapt them to your host.  For a local
> quick-start without Authelia, use the root `compose.yaml`.

opencloddie fits the existing `~/compose/edge` + `~/compose/authelia` layout:

```
                    ┌──────────────────────────────────────────────┐
  browser ──443──▶  │ nginx (edge)                                 │
                    │  ├─ /v1,/agent,/client,/install ──▶ :8788    │  API (API keys)
                    │  └─ everything else + Authelia ───▶ :8787    │  Web (Remote-User)
                    └──────────────────────────────────────────────┘
                                     │ edge network
                          ┌──────────▼───────────┐
                          │ opencloddie container│
                          │  web 8787 / api 8788 │
                          │  SQLite + sessions   │
                          └──────────────────────┘
```

The container runs **one process with two listeners**.  The web listener is
internal and trusts the `Remote-User` header injected by Authelia; the API
listener is public and authenticates `ocd_sk_...` keys.  Both share the SQLite
database and the in-memory agent hub (that is why they live in one process:
the browser terminal must reach the agent's live WebSocket).

## 1. DNS and Authelia

Point the hostname (e.g. `cloddie.example.com`) at the edge server.

Add a rule to `~/compose/authelia/assets/authelia/configuration.yml` under
`access_control.rules`.  `default_policy` is `deny`, so this is required for
the web UI:

```yaml
    - domain: cloddie.example.com
      policy: two_factor
      subject:
        - ['group:god']
```

Use `one_factor` instead of `two_factor` if that suits your policy.  The
public `/v1/`, `/agent/`, `/client/`, and `/install/` locations bypass
Authelia entirely and are protected by API keys.

Restart Authelia after editing its configuration.

## 2. nginx

Copy `deploy/nginx/opencloddie.conf` to
`~/compose/edge/assets/nginx/config/opencloddie.conf`, replace
`cloddie.example.com`, and reload:

```bash
docker exec edge-nginx-1 nginx -t && docker exec edge-nginx-1 nginx -s reload
```

It relies on the snippets already in `~/compose/edge/assets/nginx/snippets`:

* `ssl_params.conf` — TLS
* `authelia.conf` — internal auth_request endpoint
* `authelia_location.conf` — `auth_request` + `Remote-User` headers
* `proxy_params.conf` — Host, `X-Forwarded-*`, WebSocket upgrade, buffering off

The API locations explicitly blank `Remote-User` so a client cannot spoof web
identity.  The web location is the only one with `auth_request`.

Optional defence in depth: set `web.proxy_secret` in `/data/config.json` and
uncomment the matching `proxy_set_header X-OpenCloddie-Proxy-Secret ...` in the
web location.  With a mismatch the web listener returns 403.

## 3. Start the service

```bash
docker compose -f deploy/compose.yml up -d --build
```

The service joins the external `edge` network and publishes **no host ports**.
On first start it creates `/data/config.json` with a generated master secret
and an empty user database.  State lives in the `opencloddie-data` volume:

```
/data/config.json      server config + at-rest master secret
/data/opencloddie.db   users, API-key hashes, session registry
/data/logs/server.log  rotating log
```

Inspect without printing secrets:

```bash
docker compose -f deploy/compose.yml exec opencloddie opencloddie-server user list
docker compose -f deploy/compose.yml ps
```

## 4. First use

1. Open `https://cloddie.example.com/` (Authelia login).
2. **Settings → OpenCode key**: paste your `oc_sk_...` key.  It is encrypted
   at rest with `secrets.master` and never returned to the browser.
3. **API keys → Create key**: choose a model, copy the `ocd_sk_...` token once.
4. Install the client on a machine with Claude Code:

   ```bash
   mkdir -p ~/.local/bin
   curl -fsSL https://cloddie.example.com/install/opencloddie \
     -o ~/.local/bin/opencloddie
   chmod +x ~/.local/bin/opencloddie
   opencloddie login --server https://cloddie.example.com --api-key ocd_sk_...
   opencloddie
   ```

The session appears in the web UI immediately; the tab strip switches between
all connected sessions.

## Configuration reference

`/data/config.json` is generated by `opencloddie-server init --docker`.  The
important fields:

| Key | Meaning |
| --- | --- |
| `server.web_host` / `web_port` | internal UI listener (default `0.0.0.0:8787` in Docker) |
| `server.api_host` / `api_port` | public API listener (`0.0.0.0:8788`) |
| `server.public_web_url` / `public_api_url` | optional; empty derives from `X-Forwarded-Proto` + `Host` when `behind_proxy` is true |
| `server.state_dir` | logs/db directory; Docker sets `/data` via `OPENCLODDIE_STATE_DIR` |
| `server.behind_proxy` | `true` in Docker: both URLs share the public origin |
| `web.user_header` | header Authelia forwards (default `Remote-User`) |
| `web.proxy_secret` | optional shared secret header from nginx |
| `web.dev_user` | local-only fallback; keep empty in production |
| `gateway.upstream` | OpenCode Go Anthropic base URL |
| `gateway.auth_style` | `bearer` (default) or `x-api-key` |
| `gateway.models` | models shown in the UI; each has `id`, `label`, `context_tokens` |
| `gateway.default_model` | model for new API keys |
| `gateway.fallback_model` | optional one-shot retry model on 429/5xx |
| `gateway.rate_limit_per_minute` | per-API-key request limit (default 120) |
| `secrets.master` | at-rest encryption and API-key hash pepper |
| `database.path` | SQLite path (Docker: `/data/opencloddie.db`) |

Override selected values with environment variables (useful for Compose
secrets): `OPENCLODDIE_MASTER_SECRET`, `OPENCLODDIE_WEB_HOST`,
`OPENCLODDIE_WEB_PORT`, `OPENCLODDIE_API_HOST`, `OPENCLODDIE_API_PORT`,
`OPENCLODDIE_DEV_USER`, `OPENCLODDIE_PUBLIC_WEB_URL`,
`OPENCLODDIE_PUBLIC_API_URL`, `OPENCLODDIE_STATE_DIR`, `OPENCLODDIE_CONFIG`.

## Operations

**Upgrade**

```bash
git pull
docker compose -f deploy/compose.yml build --pull
docker compose -f deploy/compose.yml up -d
```

Sessions are marked offline on restart; agents reconnect automatically within
seconds and re-register their sessions (the tmux sessions keep running on the
clients).

**Backup** — back up the whole volume.  In particular `config.json` contains
`secrets.master`; without it, stored OpenCode keys cannot be decrypted and all
API keys must be reissued.

```bash
docker run --rm -v opencloddie_opencloddie-data:/data -v "$PWD":/backup \
  alpine tar czf /backup/opencloddie-backup.tgz -C /data .
```

**Key rotation** — revoke the old API key in the UI and create a new one; then
run `opencloddie login` again on clients.  Changing `secrets.master` invalidates
all stored OpenCode keys and API-key hashes.

**Health** — the image healthcheck probes both `/healthz` endpoints on
loopback.  If the container is unhealthy, check `docker compose logs`.

## Security checklist

- Never publish `8787`; it trusts `Remote-User`.
- Publish only through nginx with TLS.
- Keep `web.dev_user` empty in Docker.
- Set `web.proxy_secret` if the container network is shared with untrusted
  containers.
- The API is deliberately open to the internet; every request needs a valid
  `ocd_sk_` key and is rate limited.  Revoke keys you no longer use.
- Back up and protect `secrets.master`.
- Do not commit `/data/config.json` or the volume.
